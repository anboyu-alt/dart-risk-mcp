### B. 기존 유형·도구로 이미 커버되는 것 (4종) — 추가 불필요

- **공시·보고의무 위반** (105건, 최다) → `DISCLOSURE_VIOL`(4.3)이 「불성실공시법인」·「공시의무위반」 키워드로 이미 발화합니다. taxonomy 4.3의 정의가 "허점 악용"에 치우쳐 있어 **단순 미제출·지연**을 담기 어색하다는 점만 손보면 됩니다(정의 문구 조정 수준).
- **회계분식 세부수법** (60건) → `REVENUE_IRREG`(6.1)·`CONTINGENT`(6.2)와 `scan_financial_anomaly`의 `RESTATEMENT`·`AR_SURGE`·`INVENTORY_SURGE`가 재무 쪽에서 이미 관측합니다. 세부 수법(가공매출·재고 조작·개발비 자본화)은 **taxonomy 신설이 아니라 6.1/6.2의 카탈로그 사례**로 붙는 게 맞습니다.
- **무자본 M&A** (13건) → `SHAREHOLDER`+`FUND_OUTFLOW`+`STAKE_PLEDGE` 조합과 `capital_backflow` 패턴이 이미 담당합니다.
- **횡령·배임** (32건) → `EMBEZZLE` 존재.

### C. 이 도구 범위 밖 (10종) — 카탈로그 사례로만 남길 것

**유사투자자문·리딩방, 무차입 공매도, 선행매매·스캘핑, 사모펀드 부실운용, 금융회사
불건전영업·내부통제, 차명·타인명의 거래, 시장질서 교란행위, 가상자산** 등은 **상장회사가
내는 공시에 나타나지 않습니다.** 투자중개업자·자문업자·개인 투자자의 거래 행위이고,

이들을 taxonomy에 넣으면 `find_risk_precedents`·뷰어·`signals-data.json`까지 유형이
늘어나지만 실제 공시 스캔에서는 한 건도 발화하지 않습니다. **카탈로그 사례와 갭 리포트에

## 4. `EMBEZZLE`의 죽은 키워드 (2026-08-17 실측으로 결론 정정)

> **정정**: 이 절은 처음에 "매핑 불일치로 「시세조종」 공시가 '장외 자산 이전'으로
> 오라벨링된다"고 썼습니다. **그 오라벨링은 실제로 일어나지 않습니다** — 그런 제목의
> 공시 자체가 DART에 없기 때문입니다. 아래 실측으로 확인하고 결론을 바꿨습니다.

### 실측 — DART 공시 제목 키워드 등장 빈도

`fetch_market_disclosures`로 **2026-07-17 ~ 2026-08-15(30일), 공시 15,555건**의 제목을
스캔했습니다. (일부 날짜는 하루 1,500건 상한에 걸려 일부 누락 — 즉 "0건"은
"스캔한 15,555건 중 0건"입니다.)

| 키워드 | 제목 등장 | | 대조군 | 제목 등장 |
|---|---:|---|---|---:|
| 횡령 | 3 | | 불성실공시 | 19 |
| 배임 | 3 | | 조회공시 | 26 |
| 불공정거래 · 주가조작 · 시세조종 | **0** | | 소송 | 71 |

| 선행매매 · 차명 · 부정거래 · 공매도 | **0** | | | |

횡령·배임 3건은 전부 「횡령ㆍ배임혐의발생」(거래소 수시공시, 가운뎃점이 `ㆍ` U+318D)입니다.

### 왜 0건인가 (구조적 이유)

시세조종·미공개중요정보 이용·선행매매는 **회사가 내는 공시가 아니라 금융감독원 조사·
제재의 결과**입니다. 회사 공시에 드러나는 건 후행 신호뿐입니다 — 조회공시(`INQUIRY`),
소송, 불성실공시(`DISCLOSURE_VIOL`). 그래서 §3-C의 판단("이 도구 범위 밖")이 실측으로
뒷받침됩니다.

### 조치 (완료)

`EMBEZZLE`의 키워드 9개 중 발화 실적이 있는 **`횡령`·`배임` 2개만 남기고** 나머지 7개
(불공정거래·주가조작·시세조종·미공개정보이용·미공개중요정보·선행매매·차명)를 제거했습니다.
label이 `"횡령배임"`이라, 만에 하나 발화하면 「주가조작」류 제목을 "횡령배임"으로 표기하는
오표기 위험만 남기고 커버리지는 없었기 때문입니다. `signals.py`에 실측값과 함께 왜
지웠는지를 주석으로 남겼고, `docs/tool/signals-data.json`도 재생성했습니다.

taxonomy 매핑 `["5.3", "8.1"]`은 그대로 뒀습니다 — 횡령·배임에는 맞는 매핑입니다.

**taxonomy 7.4~7.6 신설은 하지 않기로 했습니다.** 어떤 신호도 매핑되지 않아 실제 스캔에서
절대 표면화되지 않는 유형이 3개 늘어날 뿐이고, 유형 인플레이션을 경계하는 CLAUDE.md
비범위 원칙과도 어긋납니다. 금감원 사례 159건은 갭 리포트에 참고 자료로 남습니다.

## 4-1. (참고) 원래 지적했던 매핑 구조

아래는 **정리 이전의 상태**입니다(현재 코드는 §4의 조치가 반영돼 `횡령`·`배임` 2개뿐).
왜 이런 구조가 문제로 보였는지, 그리고 왜 실제로는 발화하지 않았는지를 남겨 둡니다.

`EMBEZZLE` 신호의 키워드는 정리 전 9개였습니다:

```
횡령, 배임, 불공정거래, 주가조작, 시세조종, 미공개정보이용, 미공개중요정보, 선행매매, 차명
```

그런데 `SIGNAL_KEY_TO_TAXONOMY["EMBEZZLE"]`는 **5.3(장외 자산 이전)**과 **8.1(인위적
부실화)**로 매핑됩니다.

| id | 제목 | 정의 |
|---|---|---|
| 5.3 | 장외 자산 이전 | 특수관계자에게 공정가치 미만으로 자산을 이전하는 패턴 |
| 8.1 | 인위적 부실화 | 자산을 의도적으로 유출하거나 부채를 부풀려 부실을 유발하는 패턴 |

즉 **「시세조종 혐의발생」·「미공개정보이용」 제목의 공시가 잡히면 "장외 자산 이전" 또는
"인위적 부실화"로 라벨링됩니다.** 횡령·배임에는 맞는 매핑이지만, 같은 신호 키에 묶인
시세조종·미공개정보이용·선행매매·차명에는 의미가 맞지 않습니다.

이번 분류에서 31개 에이전트가 독립적으로 "일반 시세조종·미공개정보이용을 담을 유형이
없다"고 보고한 것도 같은 구멍입니다. 카테고리 7(시장조작·거래)에 7.1(공시 전 이상 거래)·
7.2(테마주 조작)·7.3(파생상품 남용)이 있지만, **행위 유형으로서의 시세조종·미공개중요정보
이용 자체를 담는 항목이 없습니다.**

## 5. 권고 (2026-08-17 실측 반영)

1. ~~`EMBEZZLE` 매핑 정리~~ → **완료**. 죽은 키워드 7개 제거(§4). 새 taxonomy 신설은
   실측 결과 죽은 유형이 되므로 하지 않음.
2. **4.3 정의 문구 조정** — "공시 허점 악용"에 단순 미제출·지연제출을 포함하도록 넓히거나
   절차 위반을 별도 항목으로 분리. 최다 후보(105건)가 여기 걸리고, `DISCLOSURE_VIOL`은
   실측에서 30일 19건으로 **살아 있는 신호**라 손볼 값어치가 있습니다.
3. **감사인 독립성 항목 신설 검토** — 20건, 2017년 이후 지속. 단 "감사인" 키워드는 위
   30일 스캔에서 제목 등장 0건이라, 신설 전에 **어떤 공시 제목으로 관측되는지 먼저
   확인**해야 합니다(감사인 변경·감사계약 해지 공시의 실제 제목 표기). 확인 없이
   추가하면 2번과 달리 죽은 유형이 됩니다.
4. **C군 10종은 추가하지 않음** — 카탈로그 사례·갭 리포트로만 유지. §4 실측이 이 판단을
   뒷받침합니다.

신호·유형을 추가할 때는 CLAUDE.md의 '새 신호 유형 추가' 4단계(`signals.py` →
`SIGNAL_KEY_TO_TAXONOMY` → `taxonomy.py` → 필요 시 `CROSS_SIGNAL_PATTERNS`)를 따르고,
이어서 `python scripts/export_tool_data.py`로 `docs/tool/signals-data.json`을 재생성해야
합니다(CI 자동 실행 없음). 라벨은 `data/catalog/labels_ko.json`이 단일 출처이므로 거기도
추가한 뒤 `build_md.py`를 재실행합니다.

**교훈 하나**: 유형을 추가하기 전에 그 키워드가 DART 공시 제목에 실제로 등장하는지
시장 스캔으로 먼저 재세요. §4가 그 절차 없이 내렸던 결론을 뒤집은 사례입니다.
