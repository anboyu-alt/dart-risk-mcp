# 허락이 필요한 작업 목록

자율 감사 중 발견했지만 **함부로 고치면 위험한** 것들. 각 항목은 무엇이
문제인지·왜 위험한지·어떤 선택지가 있는지를 적고, 제작자의 판단을 기다린다.

고쳐도 되는 것(사실 표기 오류, 조용한 절단, 죽은 배선 등)은 이 목록에 없다 —
그건 바로 고치고 릴리스한다.

---

## 1. 신호 신설 — 상장폐지 위기 계열의 공백

**무엇** v1.12.1에서 `INQUIRY` 키워드를 정밀화하면서
「…(상장폐지사유발생)」·「…(상장적격성실질심사대상)」·「…(개선기간부여)」류
약 60건(90일 기준)이 **어떤 신호에도 잡히지 않게** 됐다. CLAUDE.md에
「알려진 공백」으로 기록돼 있다.

**왜 위험한가** 실제로 의미 있는 상장폐지 위기 신호지만, 7.1(시장감시)이
아니라 8.x(위기·부실) 계열에 속한다. 억지로 기존 신호에 붙이면 그때 고친
오분류를 **반대 방향으로 되풀이**한다. 신호를 새로 만들면 taxonomy·phase
map·priority·패턴 연쇄가 전부 늘어난다(CLAUDE.md의 「도구 인플레이션 회피」
원칙과 충돌 가능).

**선택지**
- (a) `DELISTING_RISK`가 이미 867건/년을 잡고 있으니 그 키워드를 넓힌다 — 가장
  적은 변경이지만 그 신호의 의미가 흐려질 수 있다
- (b) 8.x에 신호를 신설한다 — 깨끗하지만 연쇄가 크다
- (c) 그대로 둔다(현재)

## 2. `_format_amount`(절삭) ↔ 뷰어 `fmtKRW`(반올림)의 1억 차이

**무엇** 같은 사실을 MCP는 「-3882억원」, 뷰어는 「-3,883억」으로 적는다.
CLAUDE.md에 **의도된 차이**로 기록돼 있다(각 레이어가 기존 유틸을 재사용).

**왜 위험한가** 통일하려면 한쪽 유틸을 바꿔야 하는데, 그 유틸은 **다른 수십
군데**가 함께 쓴다. 골든 전체가 흔들리고, 어느 쪽이 옳은지도 자명하지 않다
(손실을 절삭하면 과소 표기, 반올림하면 원문과 안 맞는 자리가 생긴다).

**선택지**
- (a) 그대로 둔다(현재, 문서화됨)
- (b) 뷰어를 절삭으로 맞춘다 — MCP가 기준
- (c) 양쪽 다 반올림 — 사용자 눈에는 자연스러우나 골든 대량 갱신

## 3. 도구 출력의 날짜 표기 혼재

**무엇** 한 리포트 안에 `20260709` · `2026.07.09` · `2026-07-09` · `26.07.09`가
섞여 나온다(각 블록이 원문 표기를 따르거나 자체 포맷을 쓴다).

**왜 위험한가** 통일하면 골든 전부가 바뀌고, **원문 표기를 그대로 보여 주는
것이 의도**인 자리(원문 인용)와 우리가 만든 표기가 구분되지 않게 될 수 있다.

**선택지**
- (a) 우리가 만드는 줄만 `YYYY.MM.DD`로 통일하고 원문 인용은 그대로
- (b) 전부 통일
- (c) 그대로 둔다(현재)

## 4. `fetch_indicator_history` — 죽은 공개 API

**무엇** `core/__init__.py`의 `__all__`에 있고 테스트도 있는데 **프로덕션
소비처가 0**이다. 폐기된 SE(스페셜 에디션) 화면용으로 만들어진 것으로 보인다
(docstring이 「이 화면」을 언급한다).

**왜 위험한가** 지우면 외부에서 import하던 코드가 깨질 수 있다(공개 API처럼
보인다). 남기면 「있는 줄 알고」 새 코드가 기대는데 실제로는 검증된 적이 없다.

**선택지**
- (a) 지운다 — SE가 폐기됐다면 소비처가 없다
- (b) 남기되 docstring에 「현재 소비처 없음」을 명시
- (c) 회전율 도구가 DART 지표를 병기하도록 실제로 쓴다(단, DART 활동성 지표는
  삼성전자조차 매출채권·매입채무 회전율이 null이라 쓸모가 제한적 — v1.21.0 실측)

같은 부류: `is_false_amendment`(2026-08-26 근본 수정으로 우회가 불필요해짐),
`summarize_note_sections`/`build_note_summary`(도구는 `classify_note_title` +
`scan_note_titles`를 직접 쓴다), `resolve_disclosure_row_from_rcept_no`
(하위 호환 래퍼, 소비처 0).

## 5. 「N개사」류 문서 수치의 재측정 불가

**무엇** CLAUDE.md에 「39개사 실측」·「12개사×3년」 같은 수치가 여럿 있는데,
그 표본 목록이 남아 있지 않아 **같은 수를 다시 만들 수 없다**.

**왜 위험한가** 지금 재측정하면 시장이 달라져 다른 수가 나온다. 문서를 고치면
그때의 근거와 어긋나고, 그대로 두면 검증 불가능한 수가 남는다.

**선택지**
- (a) 각 수치에 「측정 시점」을 병기하고 그대로 둔다
- (b) 표본 목록이 남은 것만 재측정
- (c) 그대로 둔다(현재)

## 6. `scripts/`의 조용한 상한

**무엇** 수집·백필 스크립트 여럿이 페이지 상한·건수 상한을 두는데, 상한에
닿았다는 사실을 산출물에 남기지 않는 것이 있다(도구 경로는 v1.20.x에서 고쳤다).

**왜 위험한가** 이 스크립트들은 cron으로 돌며 **비공개 데이터**(sightings·
Notion 레지스트리)를 만든다. 동작을 바꾸면 이미 쌓인 데이터와의 정합이
흔들릴 수 있고, 나는 그 데이터를 볼 수 없다.

**선택지**
- (a) 상한 도달 사실만 로그·산출물에 추가(동작 불변) — 가장 안전
- (b) 상한 자체를 올린다 — API 예산·실행 시간에 영향
- (c) 그대로 둔다(현재)

## 7. `dfOcr`/`dsRsOcr` 응답 필드 미검증

**무엇** 부도(`dfOcr`)·해산사유(`dsRsOcr`) 엔드포인트는 표본에서 발화 사례가
없어, 코드가 읽는 필드명이 실제 응답과 맞는지 **한 번도 확인된 적이 없다**.
같은 부류에서 이미 실사고가 났다(`rehabilitation`의 `rs`/`ctrcvs_rs` — 실제
필드는 `rq_rs`였고 2026-08-04에 발견).

**왜 위험한가** 실제 부도·해산이 난 회사를 찾아야 검증할 수 있는데, 그런
회사는 드물고 대개 상장폐지돼 조회가 어렵다. 추측으로 필드명을 바꾸면
**맞던 것을 틀리게** 만들 수 있다.

**선택지**
- (a) 과거 부도·해산 사례를 찾아 검증(시간이 든다)
- (b) 필드가 비었을 때 「구조화 데이터를 읽지 못했다」를 사실로 표기하도록 방어
  코드만 추가(동작 불변, 안전)
- (c) 그대로 둔다(현재)

## 8. 뷰어 피드의 「MAX」 배지 — 등급어로 읽힌다

**무엇** 공시 피드의 SIGNAL 열에 붙는 `MAX` 배지(`docs/tool/index.html`의
`badge-max`). 코드상으로는 **등급이 아니다** — `isTop`은 그 행이 이 회사의
헤드라인 신호(`CUR.heaviest.key`, `pickHeadline` 선정분)를 담고 있는지만 보고,
점수·severity 값은 배지에 닿지 않는다. 즉 「가장 무거운 신호가 여기 있다」는
**포인터**다.

**왜 위험한가** 그런데 **글자가 등급으로 읽힌다.** 「MAX = 최대·최고」다.
같은 자리의 다른 배지는 전부 한국어 사실 표기(「먼저」·「참고」·「● 신호」·
「절차·사후」)라 MAX만 튄다. v0.8.5는 등급 **어휘**를 금지하는데 hygiene
테스트의 금칙어(`매우위험|고위험|…`)가 한국어라 영문 MAX는 그물을 빠져나갔다.

**함부로 못 고치는 이유** 「HEAVIEST SIGNAL」 패널과 짝을 이루는 **디자인
결정**일 수 있고, 제작자가 쓰던 표기를 말없이 바꾸면 화면이 낯설어진다.
사실 오류가 아니라 표현 판단이라 내가 정할 문제가 아니다.

**참고(2026-08-30 추가 실측)** 같은 개념이 **공시 상세 화면에서는 이미 한국어**로
적혀 있다 — 「신호 무게: **이 기간 최상위**」, 그리고 바로 아래 「관찰 순서: 먼저 —
… (위험도 등급 아님)」. 즉 표기를 바꾼다면 새 낱말을 발명할 필요가 없고, 화면 안에
이미 쓰이는 말을 피드로 옮기면 된다.

**선택지**
- (a) 한국어 사실 표기로 바꾼다(상세 화면이 쓰는 「이 기간 최상위」) — 다른 배지와 결이 맞는다
- (b) 그대로 둔다 — 포인터지 등급이 아니고, 「HEAVIEST SIGNAL」 패널과 짝이다(현재)
- (c) hygiene 금칙어에 영문 등급어(MAX·HIGH·CRITICAL 등)를 추가하되 이 배지는
  예외로 명시 — 앞으로 새로 들어오는 영문 등급어만 막는다

## 9. `track_capital_structure`가 한정층을 쓰지 않는다

**무엇** 자본 이벤트 집계에 `qualify_signals`를 걸지 않아, 강등 대상이 그대로
세어진다. 12개사 3년 실측: **227건 중 65건(29%)**이 강등 대상이다(셀트리온
42건 중 20 · KR모터스 26건 중 11 · 진원생명과학 29건 중 10).

섞여 있는 것이 한 종류가 아니다.

- **정정**(R5, 「[첨부정정]주요사항보고서(유상증자결정)」) — 이미 센 사건의 정정
- **결과 보고**(R2·R2c, 「…발행결과」·「…청약결과」) — 이미 센 결정의 결과
- **자회사 사안**(R3) — 이 회사의 자본이 아니다
- **되사기·소각**(방향 안내, 「자기전환사채만기전취득결정」) — ⚠ 이건 **이 도구가
  일부러 세는 것**이다. `CHURN_NON_DILUTIVE_MARKS`로 희석성/비희석성을 이미
  가른다

**왜 위험한가** 앞의 셋은 빼는 게 맞지만 **넷째는 빼면 안 된다.** 일괄로 걸면
비희석성 집계가 무너진다 — `check_disclosure_anomaly`의 ⑤ 조회공시에서 같은
실수를 한 번 했다(한정층을 그대로 걸었더니 회사 쪽 기록만 있는 회사가 0이 됐다).

선별하려면 강등 **사유를 구분**해야 하는데 `Qualified`에는 규칙 id가 없고
한국어 `reason` 문장뿐이다. 문장 매칭은 깨지기 쉽고, `Qualified.rule`을
신설하는 것은 소비처 5곳이 걸린 **core API 변경**이다.

그리고 이 집계는 표시가 아니라 **`CAPITAL_CHURN` 플래그의 입력**이다 — 건수가
바뀌면 「12개월 3건 이상」 판정이 바뀐다.

**선택지**
- (a) `Qualified`에 규칙 id를 신설하고 정정·결과보고·자회사만 뺀다(정확하지만
  core API 변경 + 소비처 5곳 회귀 검증)
- (b) 제목 기준으로 정정·결과보고만 좁게 뺀다(`is_amendment_disclosure` 확장
  없이 이 도구 안에서만) — 범위는 작지만 규칙이 두 곳에 생긴다
- (c) 그대로 두고, 화면에 「정정·결과 보고가 포함된 횟수」임을 밝힌다(판정 불변)
- (d) 그대로 둔다(현재)
