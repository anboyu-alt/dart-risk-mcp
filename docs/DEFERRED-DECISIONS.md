## 3. ~~도구 출력의 날짜 표기 혼재~~ — **해소 확인(2026-08-30)**

**전제가 달랐다.** 골든 전수를 겹침 없이 세고 원문 인용 골든을 분리했다.

    도구 생성  5,580   YYYYMMDD 5,123(92%) · YYYY.MM.DD 314 · YYYY-MM-DD 134 · YYYY-MM 9
    원문 인용    394

우리가 만드는 표기는 **`_fmt_date8` 하나뿐**이고 일관되게 `YYYY.MM.DD`다.
`YYYYMMDD`가 아닌 것은 전부 **값의 출처**가 그 표기다 — `affiliates`
최초취득일·`fund_usage` 납입일은 DART가 점 표기로 주고, 대시 표기는 금감원
카탈로그 보도자료 날짜(61)와 `majorstock`의 `rcept_dt`(23)다. 즉 선택지 (a)
「우리가 만드는 줄만 통일」은 **이미 참**이었고, 남은 혼재를 없애려면 DART가
준 문자열을 다시 써야 한다 — 그러면 이 항목이 스스로 경고한 위험(원문 표기와
우리 표기의 구분 소멸)이 현실이 된다.

**부수 발견 1** `search_market_disclosures`의 창 라벨이 같은 포맷을 **손으로
한 번 더 조립**하고 있었다(출력은 같지만 8자리가 아니면 쓰레기가 나온다).
헬퍼 호출로 바꿨다.

**부수 발견 2** `majorstock.json`의 `rcept_dt`는 **`2026-06-08`**로 온다 —
같은 이름의 필드가 `list.json`에서는 `20260608`이다. 렌더가 `len(dt) == 8`로
갈라 통과시키는데, 이걸 버그로 보고 `dt[:8]`로 자르면 **`2026-06-`**가 된다.

⚠ **1차 측정이 두 군데 틀렸다** — `YYYY-MM` 정규식이 `YYYY-MM-DD`의 앞부분을
겹쳐 세 두 수가 항상 같았고, 원문 골든 판별이 `stem.startswith("doc_")`인데
파일명은 `회사_doc_…`라 한 건도 안 걸려 「원문 인용 0」이 나왔다.

`tests/test_date_format_sources.py`가 고정.

## 4. ~~`fetch_indicator_history` — 죽은 공개 API~~ — **처리됨(2026-08-30)**

제작자 승인으로 처리. **목록이 두 방향으로 틀려 있었다.**

AST 전수(정규식이 아니라 `ast.Call`)로 재보니 미사용 공개 함수는 5개가 아니라
**7개**였고, 지목된 것 중 `build_note_summary`는 **실제로 쓰이고 있었다**
(`server.py:3670`).

    calculate_risk_score          v0.8.5가 점수 노출을 금지하며 렌더에서 빠졌다
    estimate_crisis_timeline      「위기 타임라인」이 v0.8.5로 출력에서 제거됐다
    fetch_executive_roster        `_detail` 판으로 대체됐다
    fetch_indicator_history       폐기된 SE(#239) 화면용
    is_false_amendment            2026-08-26 근본 수정으로 우회가 불필요해졌다
    resolve_disclosure_row_…      하위 호환 래퍼
    summarize_note_sections       도구가 `classify_note_title`+`scan_note_titles`를 직접 쓴다

### 지우지 않았다 (선택지 (b))

이 패키지는 **PyPI에 배포된다**(`publish-pypi.yml` · README `pip install
dart-risk-mcp`). `core.__all__`은 외부에서 import 가능한 진짜 공개 API라,
삭제는 되돌리기 어려운 **외부 영향**이다.

그리고 위험 목록의 「검증된 적이 없다」는 표현도 정확하지 않았다 — 이것들은
**테스트가 있다**(각 3~21개 호출). 「검증 안 된」 코드가 아니라 「검증됐지만
안 쓰는」 코드다.

### 대신 한 것

1. 각 함수 독스트링에 **「현재 프로덕션 소비처 0」** 명시 — 다음 사람이
   「있으니 쓰면 되겠지」 하지 않도록. `is_false_amendment`는 독스트링이
   **없어진 호출부를 설명**하고 있어서 그것도 바로잡았다.
2. `server.py`의 **죽은 import 2개 제거**(`calculate_risk_score`·
   `estimate_crisis_timeline`) — 내부 변경이라 외부 영향 없음. 특히 점수 함수가
   서버 네임스페이스에 남아 있던 것은 v0.8.5 관점에서도 정리할 값이었다.
3. **`tests/test_unused_exports.py`로 목록을 못 박았다** — 위험 목록이 적은
   진짜 문제(「있는 줄 알고 새 코드가 기댄다」)의 durable한 해법이다. 새 죽은
   export가 생기면 실패하고, 쓰이게 되면 목록에서 빼라고 실패한다.
4. CLAUDE.md의 낡은 서술 정정 — `find_actor_overlap`이 `fetch_executive_roster`를
   쓴다고 두 곳에 적혀 있었으나 실코드는 `_detail` 판을 쓴다.

### 삭제를 원한다면

(a)는 여전히 가능하지만 **deprecation 주기**를 거쳐야 한다 — 한 릴리스에서
`DeprecationWarning`을 붙이고 다음 메이저에서 제거. 지금 판단으로는 얻는 것
(코드 몇 줄)보다 잃는 것(외부 import 파손 가능성)이 크다.

## 6. ~~`scripts/`의 조용한 상한~~ — **처리됨(2026-08-30, 선택지 (a))**

`backfill_corp_aliases.py`·`backfill_renames.py`는 30일 청크 × `max_pages=60`
(= 6,000건)으로 훑는다. 두 독스트링 다 「90일이면 상한에 걸리므로 30일 청크로
순회한다(**누락 방지**)」라 적으면서, **그 30일 청크가 다시 상한에 닿았는지는
보지 않았다**. 닿으면 그 청크 뒷부분이 조용히 사라진다 — 별칭이면 그 회사가
옛 이름으로 검색되지 않고, 개명이면 행위자 이름 병합이 그만큼 빠진다.
`backfill_sightings.py`는 같은 자리에서 이미 청크별 절단을 세어 알리고 있었다
(셋 중 둘만 빠져 있었다).

**상한도 청크 길이도 올리지 않았다** — 예산·실행 시간이 달라지고, 이미 쌓인
비공개 데이터와의 정합이 흔들린다. **닿았다는 사실만** 알린다.

⚠ **한 번 위험하게 짰다가 되돌렸다.** 처음엔 `collect_renames`의 반환 dict에
`_truncated_chunks` 키를 넣었는데, 그 dict는 **키가 corp_code**라 `main`의
`e["names"]`가 죽고 `merge_renames`가 그 키를 **비공개 sightings 파일에 써
넣는다**. 이 항목이 경고한 바로 그 위험이었다. 로그로만 알리고,
`backfill_corp_aliases`는 이미 따로 반환하는 `stats`에 담았다.

`tests/test_backfill_cap_reporting.py`가 고정(상한 값 불변까지 함께).

붙였다. 요약·해석·측정 수치를 덧붙이지 않았다 — 그것이 이 항목이 경고한
「없는 근거를 지어낼 위험」이다. 블록 머리에 **「커밋에서 재구성했다」**를
명시했다.

이 레포의 커밋 제목은 관례상 그 자체로 사실을 서술하므로(「채무증권 잔액이
항상 비어 있던 문제 — 도구 하나가 통째로 죽어 있었다」) 제목만으로도 쓸모가
있고, 더 알고 싶으면 PR 링크를 따라가면 된다.

    구간 커밋 50개 · 그중 릴리스 커밋 18개를 뺀 32개 변경이 항목으로 들어갔다
    가장 이른 것 #315(채무증권 잔액) · 가장 늦은 것 #363(뷰어 자기자본 대비)

`CLAUDE.md`에 있다 — 재구성으로 그것을 복원하지 않는 것이 이 선택의 요점이다.
