# DART 공시 도구 4종 비교 — 무엇을 할 수 있고, 왜 그런가

측정일 2026-09-12 · 네 도구를 같은 세션에서 실제로 호출해 확인한 기록이다.
표에 적힌 수치·문구는 전부 그날 응답에서 옮긴 것이고, 재현 근거는 문서 끝의
「실측 로그」에 있다.

---

## 0. 한 줄로

| 도구 | 한 줄 |
|---|---|
| **DartLens** | 공시 본문을 **미리 긁어 DB에 넣어 둔** 곳. 그래서 **회사를 모른 채** 주석을 찾을 수 있다. |
| **darty** | 공시 **한 건을 그때그때 받아 임베딩**해 그 안을 묻는다. 미리 쌓아 둔 것이 없다. |
| **korean-dart** | OpenDART **API를 거의 그대로** 열어 준다. 첨부파일·XBRL까지 닿는다. |
| **DART 리스크 분석**(우리) | 같은 API를 받아 **불공정거래 위험 신호로 해석**한다. 조회가 아니라 판정이 산출물이다. |

**넷은 경쟁 관계가 아니다.** 서로 다른 층에 있다 —
`원자료 접근(korean-dart)` → `본문 검색(DartLens·darty)` → `해석(우리)`.

---

## 1. 구조가 능력을 정한다

각 도구가 못 하는 일은 대개 설계 실패가 아니라 **구조에서 따라 나온 결과**다.

### 1-1. DartLens — 자체 DB + 주석 색인

응답이 스스로 밝히는 범위:

> 상장사 포함 **46,079곳** · **2023년부터** 지금까지 · 연간과 1·2·3분기 ·
> 연결과 별도 (재무 수치는 2022년부터)

즉 DART 원문을 **미리 수집·파싱해 문서 단위로 저장**해 두었고, 주석마다
`document_id`가 붙는다. 여기에 두 겹의 색인이 얹혀 있다.

- **낱말 사전**(FTS) — `terms_lookup`이 **밀리초**에 답한다. 「계속기업」43,280건·
  8,527곳, 「전환사채」161,292건·3,927곳. 이건 뜻이 아니라 **이 DB에서만 나오는 통계**다.
- **임베딩** — `similarity` 점수와 `search_mode: "keyword_then_semantic"`이 응답에 있다.

**그래서 되는 것**: 회사를 지정하지 않고 「전환사채를 발행했고 계속기업
불확실성도 적은 주석」을 찾을 수 있다. 실측 — 2025년 두 조건을 **모두** 채운 주석
**2,540건 · 783곳**(낱말 하나만 적힌 것은 57,071건). OpenDART API에는 이런 질의가
**아예 없다**.

**그래서 안 되는 것**:
- **2023년 이전은 없다.** 수집 시작점이 거기다.
- **수집되지 않은 접수가 있다.** 응답의 `collect_state`가 `ok`가 아니면 그
  접수번호로는 주석·재무가 안 나오고, 도구가 스스로 "그때는 dart_url을
  안내하는 편이 정확하다"고 적는다.
- **주요사항보고서는 19종만** 다룬다(`event_kind` enum). 지분공시·거래소공시는 없다.
- **판정하지 않는다.** 신호·패턴·위험 해석이 없고, 답변 규칙이 오히려
  「원문을 그대로 인용하라」로 되어 있다.
- **유료 서비스다.** `plan: free`(베타) · `paid_until: 2026-09-18` · 분당 30회.
  제3자 서버에 의존하므로 그쪽이 닫히면 능력도 사라진다.

### 1-2. darty — 공시 한 건을 그때 임베딩

`get_disclosure`를 부르면 응답이 그대로 말해 준다:

```
이미 저장된 공시입니다: 20260324000035.xml
임베딩 완료: 101개 청크 (text-embedding-3-small)
```

**문서 하나를 받아 → 청크로 쪼개 → OpenAI 임베딩 → 그 문서 안에서만 검색**한다.
미리 쌓아 둔 코퍼스가 없으니 **먼저 `get_disclosure`를 불러야** `search_disclosure`가
동작한다(도구 설명에 그렇게 적혀 있다).

**그래서 되는 것**: 사업보고서처럼 **수백 KB짜리 한 건**에서 「내가 찾는 표가
어느 절에 있나」를 자연어로 집어낸다. `sections` 인자로 목차 1~11번 중 어디를 볼지
좁힐 수도 있다.

**그래서 안 되는 것**:
- **전 회사 검색이 불가능하다.** 구조상 색인이 한 건씩만 쌓인다.
- **출력이 DART 원본 XML 그대로다.** 실측 결과에 `<TE ACODE="CB_PR">606</TE>`,
  `<TU AUNIT="INC_DT" AUNITVALUE="20210623">` 같은 태그가 그대로 실려 온다 —
  마크다운 변환이 없다. 사람이 읽기 어렵고 컨텍스트를 많이 먹는다.
- **재무 섹션이 기본 제외다**(`include_financial: false`). 재무는 별도 API로 가라는
  설계다.
- 첫 호출에 **다운로드+임베딩 비용**이 든다.

### 1-3. korean-dart — OpenDART를 넓게, 얇게

OpenDART 엔드포인트를 거의 1:1로 열고, 여기에 셋을 더했다.

- **`dart_raw` 패스스루** — 전용 도구가 없는 엔드포인트도 `operation` 이름만
  주면 호출된다. 새 API가 생겨도 코드 수정 없이 닿는다.
- **첨부파일 접근** — OpenDART 표준 API에 첨부 엔드포인트가 **없어서**, DART
  뷰어 HTML을 스크래핑해 우회한다. 실측(CSA 코스믹 사업보고서): PDF 1건 +
  IFRS 원문 XBRL ZIP 1건을 목록으로 돌려주고 `extract` 모드로 HWP/PDF/XLSX를
  마크다운으로 뽑는다. **이 셋 중 첨부에 닿는 유일한 도구다.**
- **XBRL** — `markdown_full`은 taxonomy 전체 계정 + 계산 검증까지 한다.
- 프리셋 22종·정기보고서 섹션 29종 enum으로 자주 쓰는 조회를 묶었다.

**그래서 안 되는 것**:
- **본문을 검색하지 못한다.** `download_document`가 마크다운으로 통째로 주지만
  (기본 10만 자에서 절단) 그 안을 찾아 주지는 않는다.
- **파생 도구 2종은 얕다.** `disclosure_anomaly`는 정정비율·감사인 교체·감사의견·
  자본 스트레스 4개로 **0~100점**을 매기고, `buffett_quality_snapshot`은 ROE·부채
  기준 투자 스크리닝이다. 관점이 **투자 판정**이고 불공정거래 탐지가 아니다.
- 스크래핑 경로는 **DART 뷰어 HTML이 바뀌면 깨진다**(구조적 취약점).

### 1-4. DART 리스크 분석(우리) — 판정층

같은 OpenDART 위에 **해석 계층**을 얹었다. 조회 결과가 아니라 **읽은 결과**가
산출물이다.

- **신호 58종 / 8카테고리** — 공시 제목을 키워드로 분류.
- **한정층(`qualifiers`)** — 같은 제목이라도 「제출인이 회사가 아니다」(R1)·
  「이미 끝난 건의 사후 보고다」(R2)·「자회사 사안이다」(R3)면 **관찰 신호에서
  강등**한다. 제목 매칭만 하면 삼성전자 연간 발화 8건이 **전부 오탐**이었다.
- **복합 패턴 11종** — 무자본 M&A·자금 역류·조달-유용 체인 등. 신호 조합 +
  **관찰 윈도우**(250개사×5년 실측으로 재보정) + **비례 임계**(60%)로 발화.
- **원문 확인 게이트** — 제목만으로 정상/이상이 안 갈리는 패턴은 원문을 열어
  거래상대방의 **관계**(계열·종속·외부)를 확인해야만 표시한다.
- **금감원 적발 사례 277건 카탈로그**를 taxonomy에 매핑.

**그래서 안 되는 것**(대부분 **의도적 비범위**):
- **점수·등급을 매기지 않는다**(v0.8.5 원칙). 정량화는 법적 판단·투자 권유로
  읽힐 수 있어서다. `disclosure_anomaly`가 0~100점을 내는 것과 정반대 선택.
- **매수/매도 추천·가격 예측 없음.**
- **업종 평균 비교 없음** — DART API가 제공하지 않는다(검증 완료).
- **전 회사 본문 검색 없음** — `search_notes_in_report`는 **한 보고서 안에서만**
  돈다. 도구 설명과 출력 머리글 양쪽에 그 사실을 적어 두었다. 그러려면
  DartLens 같은 사전 색인 DB가 있어야 한다.
- **실시간 알림·시장 전체 일일 자동 스캔 없음**(호출 한도 + 책임 영역 분리).
- **첨부파일(PDF/HWP)에 닿지 않는다** — ZIP 안의 XML 본문만 읽는다.

## 3. 같은 질문, 세 도구 — 실측 대조

**질문**: CSA 코스믹(083660)의 사모자금 사용 내역.

### korean-dart — 원자료 그대로

`get_periodic_report(report_type="private_placement_fund_use", year=2025)` →
**5건**. OpenDART `prvsrpCptalUseDtls` JSON을 손대지 않고 준다.

```json
{ "tm": "15", "pay_de": "2021.06.23", "pay_amount": "-",
  "real_cptal_use_dtls_cn": "원재료 매입",
  "mtrpt_cptal_use_plan_useprps": "1,500" }
```

- `pay_amount: "-"` — DART가 **미기재를 `"-"`로 준다**. 그대로 노출된다.
- `mtrpt_cptal_use_plan_useprps`가 「1,500」 — **용도 칸에 금액이 들어 있다**
  (제출사가 그 칸을 다르게 채웠다). 해석하지 않고 전달한다.
- **2025 사업보고서 한 건**만 본다. 다른 연도 보고서는 따로 불러야 한다.

### darty — 원문 조각

`search_disclosure(query="...전환사채 발행 내역")` → 해당 절을 찾아내지만,
돌아오는 것은 DART 원본 XML이다:

```xml
<TE ACODE="CB_PR">606</TE>
<TU AUNIT="PYM_DT" AUNITVALUE="20210623">2021년 06월 23일</TU>
```

**절을 정확히 찾은 것은 맞다**(7. 증권의 발행을 통한 자금조달에 관한 사항).
다만 값을 쓰려면 태그를 사람이 걷어내야 하고, 응답 하나가 컨텍스트를 크게 먹는다.

### 우리 — 해석된 결과

`track_fund_usage(lookback_years=2)` → **11건**(여러 연도 보고서 스냅샷을 조달건
단위로 접은 결과. 같은 5건이 아니다).

```
[2025 사모] 납입일 2025.09.25
  계획: 9,999 (9,999,000,000원)
  실제: 운영자금 (0원)
  차이사유: 납입 전
  ℹ️ 납입일 2025.09.25이 이 보고서 결산일 2025.06.30 이후입니다 —
     이 보고서 시점에는 아직 납입 전이라, 집행 내역이 비어 있는 것을
     미보고로 보지 않았습니다.

…전체 11건 중 10건을 표시했습니다 · 계획·실제가 모두 미기재인 1건 제외.
```

세 가지가 앞의 둘에 없다.

1. **전제 검증** — 「실제 0원」을 자동으로 유용 의심으로 올리지 않는다.
   `pay_de > stlm_dt`면 **아직 돈이 안 들어온 것**이라 판정을 억제하고 그 이유를
   화면에 남긴다. (이 가드가 없던 판은 *"받은 돈이 어디에 쓰였는지 보고되지
   않고 있습니다"*를 **돈이 오기도 전에** 출력했다.)
2. **미기재 정규화** — `"-"`를 빈 값으로 접고, 껍데기 행은 목록에서 빼되
   **몇 건을 뺐는지 적는다**.
3. **다년 접기** — 같은 조달건이 여러 보고서에 되풀이 실리는 것을 조달건 단위로
   묶고 가장 최신 스냅샷을 대표로 둔다.

**요약**: korean-dart는 **정확하지만 날것**, darty는 **찾아 주지만 태그째**,
우리는 **해석하되 판정 근거와 제외 건수를 함께 적는다**.

## 4. 언제 무엇을 쓰나

| 상황 | 도구 |
|---|---|
| 「이런 회계처리를 한 회사를 찾아 줘」 (회사를 모름) | **DartLens** — 유일하게 가능 |
| 「이 낱말이 공시에 몇 건이나 나오나」 | **DartLens** `terms_lookup` |
| 「이 사업보고서 어디에 그 내용이 있나」 | **darty** 또는 **우리** `list_disclosure_sections` |
| 「첨부된 감사보고서 PDF를 읽어 줘」 | **korean-dart** — 유일하게 가능 |
| 「XBRL 원본 태그가 필요해」 | **korean-dart** |
| 「이 회사에 이상한 낌새가 있나」 | **우리** `analyze_company_risk` |
| 「이 두 회사에 같은 사람이 있나」 | **우리** `find_actor_overlap` |
| 「CB 전환되면 몇 % 희석되나」 | **우리** `track_capital_structure` |
| 「투자할 만한 회사인가」 | **korean-dart** `buffett_quality_snapshot` (우리는 비범위) |
| 2022년 이전 자료 | DartLens 제외 나머지 셋 |

**조합이 가장 강하다.** 예: DartLens로 전 회사에서 후보를 찾고 → 우리 도구로 그
회사의 신호·패턴을 보고 → korean-dart로 첨부 원문을 확인한다.

## 5. 우리 도구가 지금 메울 수 있는 것 / 메울 수 없는 것

이 비교에서 드러난 우리의 공백을 정직하게 적는다.

| 공백 | 메울 수 있나 | 판단 |
|---|---|---|
| **첨부 PDF/HWP 파싱** | 가능하지만 **안 한다** | 의존성 최소화 원칙(`mcp`+`requests`만). PDF 파서는 `pypdf`가 카탈로그 그룹 전용으로만 있다. 넣으려면 런타임 의존성 경계가 무너진다. |
| **XBRL 전체 태그** | 가능 | 지금은 감가상각비만 좁게 뽑는다. 필요가 생기면 범위를 넓힐 수 있다. |
| **전 회사 본문 검색** | **불가능** | 사전 수집·색인 DB가 있어야 한다. OpenDART API만으로는 원리적으로 못 한다 — DartLens가 DB를 두는 이유가 바로 이것이다. |
| **투자 스크리닝** | 가능하지만 **안 한다** | 비범위(v1.0 GA 영구 확정). |
| **점수·등급** | 가능하지만 **안 한다** | v0.8.5 원칙. |

「전 회사 본문 검색」만이 **구조적으로 불가능한 공백**이고, 나머지는 전부
**의도적으로 하지 않기로 한 것**이다.
