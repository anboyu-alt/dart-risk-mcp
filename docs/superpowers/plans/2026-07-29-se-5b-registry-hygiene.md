# SE-5b 행위자 레지스트리 위생 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 반복 등장이 **정상인** 제도권 기관이 "반복 등장 행위자" 상위를 차지해 진짜 세력을 가리는 문제를 없앤다.

**Architecture:** 필터(`should_store`)와 정규화(`normalize_name`)는 **이미 core에 있고 정상 작동한다.** 결함은 읽기 경로가 그것들을 쓰지 않는다는 것이다. `known_actors.py`의 로드·조회 경로에 필터를 걸고, 정규화에 HTML 엔티티 제거를 더한다. **비공개 Notion DB는 건드리지 않는다** — 지울 목록을 보고하는 스크립트만 만들고 실행은 제작자가 한다.

**Tech Stack:** Python(core, 표준 라이브러리만), pytest.

## Global Constraints

- **판정 금지 (v0.8.5).** 레지스트리는 사실 표기다. 이 계획은 무엇이 노이즈인지만 다루고, 남은 인물에 대해 어떤 평가·점수·순위도 만들지 않는다.
- **제작자의 비공개 Notion DB를 수정하지 않는다.** 삭제는 되돌리기 어렵고 외부에 영향을 준다. 스크립트는 **보고만** 한다.
- **사람이 일부러 넣은 등재를 지우지 않는다.** 읽기 필터는 `auto_matched`(기계 등재)에만 적용한다. `verified`·`maintainer_seed`는 그대로 통과시킨다 — 제작자가 판단해 넣은 것이기 때문이다.
- **`dart_risk_mcp/` 변경이 MCP 도구 26개에 미치는 영향을 명시한다.** 이 계획은 `lookup_known_actor`·`find_actor_overlap`·`analyze_company_risk`·`build_event_timeline`의 출력을 **의도적으로** 바꾼다(노이즈 제거). 그 외 도구는 영향이 없어야 한다.
- **외부 의존성 추가 금지.**
- **레지스트리 미설정 시 동작을 바꾸지 않는다.** Notion 자격증명이 없으면 지금처럼 조용히 빈 레지스트리로 동작해야 한다.

### 결함 2 — `normalize_name`이 HTML 엔티티를 남긴다

원문 파싱에서 `&CR;`가 이름에 새어 들어와 **같은 실체가 둘로 쪼개진다.** 실측 4건:

```
SBI-KIS 2018 투자조합&CR;업무집행조합원 SBI인베스트먼트
미래에셋대우 주식회사&CR;(지브이에이 FORTRESS-A ...)
삼성전자 &CR;주식회사
케이파트너스&CR;주식회사
```

`normalize_name`으로 합쳐지는 중복 쌍 3개 중 2개가 이 때문이다:

```
'삼성전자 주식회사'  ← ['삼성전자 주식회사', '삼성전자 &CR;주식회사']
'SBI-KIS 2018 투자조합 업무집행조합원 SBI인베스트먼트'
                    ← [..., 'SBI-KIS 2018 투자조합&CR;업무집행조합원 SBI인베스트먼트']
```

**관련기업 태그(`companies`)에는 엔티티가 0건이다** — 인물명에만 있다. 발견된 엔티티는 `&CR;` 한 종류뿐이지만, 같은 파싱 경로에서 다른 엔티티가 나올 수 있으므로 일반 패턴으로 처리한다.

세 번째 중복 쌍은 엔티티와 무관하다(`시너지투자자문 주식회사` vs `… (투자일임업자의 지위에서)` — 이미 역할 괄호 제거로 합쳐진다).

### 이미 있어서 만들지 않는 것

- `should_store`(`known_actors.py:350`) — 정상 작동. **재구현 금지.**
- `normalize_name`(`known_actors.py:116`) — 역할 괄호 제거·공백 단일화·대문자 통일이 이미 있다. 엔티티 제거만 더한다.
- `_INSTITUTION_PAT`(`:249`)·`classify_actor`·`sector_of` — 손대지 않는다.

## Task 1: `normalize_name`에 HTML 엔티티 제거

**Files:**
- Modify: `dart_risk_mcp/core/known_actors.py`
- Test: 기존 `normalize_name` 테스트가 있는 파일(먼저 찾아라)

**Interfaces:**
- Modifies: `normalize_name(name) -> str`. 기존 동작(역할 괄호 제거·공백 단일화·대문자화)은 **그대로 두고** 엔티티 제거를 **앞단에** 더한다.

**요구사항:**

- `&CR;` 같은 HTML 엔티티(`&`로 시작해 `;`로 끝나는 짧은 토큰)를 **공백 하나로** 치환한다. 빈 문자열로 지우면 `삼성전자&CR;주식회사` 같은 붙은 형태에서 토큰이 뭉개진다 — 실측 `케이파트너스&CR;주식회사`가 그 형태다. 공백으로 치환한 뒤 기존 공백 단일화가 정리한다.
- **패턴을 좁게 잡아라.** `&`가 정상적으로 들어가는 회사명이 있다(`S&T중공업`, `AT&T`). `&` 뒤에 영숫자 1~8자와 `;`가 오는 경우만 엔티티로 본다. `S&T중공업`은 `;`가 없어 해당되지 않는다.
- 기존 호출자(`lookup_actor`·`lookup_actors_by_company`·`fold_variants`·`discover_actors.py`·`manage_aliases.py`·`diagnose_exits.py`)의 동작이 깨지면 안 된다.

- [ ] **Step 1: 실패하는 테스트를 쓴다**

기존 테스트 파일의 컨벤션을 먼저 읽고 따르라. 검증할 것 (**실측값 그대로**):

1. `normalize_name("삼성전자 &CR;주식회사") == normalize_name("삼성전자 주식회사")`
2. `normalize_name("케이파트너스&CR;주식회사") == normalize_name("케이파트너스 주식회사")` — **붙어 있는 형태**. 엔티티를 빈 문자열로 지우면 `케이파트너스주식회사`가 되어 이 테스트가 실패한다(그게 이 테스트의 목적이다)
3. `normalize_name("SBI-KIS 2018 투자조합&CR;업무집행조합원 SBI인베스트먼트")`가 `&CR;` 없는 형태와 같다
4. **`S&T중공업`이 손상되지 않는다** — `normalize_name("S&T중공업")`에 `S&T`가 남아 있다
5. `AT&T` 같이 `&` 뒤에 문자가 오지만 `;`가 없는 이름도 손상되지 않는다
6. 엔티티가 없는 이름의 결과가 **이전과 완전히 동일하다**(회귀 방어 — 기존 테스트가 이미 있으면 그것으로 충분)

## Self-Review 결과

- **가장 큰 위험은 과잉 삭제**다. 필터는 `should_store`가 거부 + 전 기록이 기계 등재, 두 조건을 모두 만족할 때만 작동한다. Task 2의 검증 3·5·8번이 그것만 노린다.
