# SE-8 실사용 피드백 반영 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SG 법인을 실제로 분석해 본 사용자가 지적한 11건을 반영한다. 원본 DART 코드·영문 필드명이 번역 없이 새는 문제, 표 열 순서가 이용자 우선순위와 반대인 문제, 근거 없는 각주 표기, 강조 누락을 고친다.

**Architecture:** 대부분 `docs/tool/se/app.js`(값 라벨 매핑·순수 로직)와 `docs/tool/se/ui.js`(렌더 순서)의 국소 수정이다. `dart_risk_mcp/core/`는 감사보수 필드 정책 정합(추가 없음, 표시 생략) 하나만 SE 쪽에서 대응한다. 새 메커니즘을 만들지 않고 **이미 있는 것**(`isAggregateRow`/`splitAggregateRows`, `MARK_RULES`, `REPRT_CODE_LABELS` 패턴)을 재사용한다.

**Tech Stack:** 순수 ES5 스타일 JS, CSS, pytest + node 서브프로세스.

## Global Constraints

- **판정 금지 (v0.8.5).** 이 계획은 전부 "읽기 쉽게" 문제이지 새 판정을 추가하지 않는다. 새로 추가하는 강조(자금사용 계획≠실제)도 SE-4g 규칙(부호·두 값 비교·DART 원본 값)을 벗어나지 않는다.
- **재지 않은 값을 실측이라 적지 않는다.** 이 계획의 모든 실측값은 SG(`corp_code=00963976`) 실 API 응답에서 직접 뽑았다. 의심되면 다시 재라.

### ① 공시 목록 "코"·"정"·"코정" — DART 공식 비고 코드, 번역 없음

`fetch_company_disclosures`의 `rm` 필드 실측값: `{'연', '정', '코', '코정'}`. `app.js`의 `LABELS`엔 `rm: "비고"`(컬럼 헤더 번역)만 있고 **값 자체는 번역이 없다.** DART 공식 코드: `유`=유가증권, `코`=코스닥, `채`=채권상장법인, `넥`=코넥스, `공`=공정위 대상 기업집단, `연`=연결대상 종속회사 있음, `정`=정정신고, `철`=철회. 조합값(`코정`)도 나온다 — 문자 단위로 분해해 이어붙여야 한다.

### ② 공시 목록 — 열 폭이 내용과 무관하게 균일

`index.html:81~82`: `th,td{...max-width:280px}` — **모든 표, 모든 열에 같은 상한.** `report_nm`(공시명, 긴 텍스트)과 `flr_nm`(공시제출인, 짧은 이름)이 똑같이 280px다. 지금은 공시명이 좁아 잘리고 제출인 칸은 남는다.

### ③ 타법인 출자 "나머지 1개열" — 접힘 최소 단위가 없다

`splitVisibleFolded`(`app.js:506`)는 `MAX_VISIBLE_COLUMNS(12)`를 넘으면 초과분을 **몇 개든** 접는다. 20개 필드 표에서 필수 열(essential) 배정에 따라 접히는 수가 1개가 될 수 있다 — 이 경우 "나머지 1개열" 버튼 하나 누르자고 클릭을 요구하는 건 배보다 배꼽이 크다.

### ④ 자금 조달건의 "차이 사유" — DART가 각주 마커만 주고 본문이 없다

실측(`fetch_fund_usage`, SG): 차이 사유 있는 8건 전부 `dffrnc_resn == '주1)'`. **이건 우리 버그가 아니라 DART API 응답 자체가 각주 마커만 주는 것이다** — 각주 본문은 공시 원문(사람이 읽는 문서)에만 있고 API 구조화 데이터엔 없다. 지금 화면은 이걸 완결된 사유처럼 그대로 보여준다.

### ⑤ 자금 사용 — `kind` 원문 "public"/"private", 계획≠실제 강조 없음

실측 `kind` 값: `{'public', 'private'}`. `LABELS`엔 `kind: "구분"`(헤더)만 있고 **값 라벨이 없다.** 공모/사모로 번역해야 한다.

`fund_usage`는 `MARK_RULES`에 항목이 **없다**(`grep` 0건). `fundChain`의 `uses[]`는 이미 `plan`·`real`을 나란히 갖고 있어 `real !== plan`은 **DART 원본 두 값의 비교**(SE-4g 규칙에 정확히 부합)인데 강조가 안 걸린다.

### ⑥ 재무 파생 지표·원본 재무제표 — 열 순서가 분류 메타를 앞에 둔다

`financialRatios`(`app.js:1451~1476`)의 반환 키 순서: **`구분(연결/별도) → 기간 → 지표 → 값 → 계산식 → 재료`.** 이용자가 보고 싶은 "무슨 지표가 얼마인지"가 3~4번째다.

원본 재무제표 표(`financials` 섹션)도 같은 패턴이다(`app.js:1975` 주석): `fs_div·sj_div·fs_nm·sj_nm`(연결/별도, 재무상태표/손익계산서 구분)이 `account_nm`(계정과목)보다 앞선 열로 노출된다.

**일반 원칙 문제다** — "표를 구성할 때 이용자에게 어떤 정보가 유용할지 고민부터 하고 배치해야 한다"는 지적은 이 두 표에 국한되지 않을 수 있다. Task 4에서 이 두 표를 고치고, 같은 패턴이 다른 표에도 있는지 점검한다.

### ⑦ 지표 설명 커버리지 — 22/66만 뜻이 있다

SE-4h가 `INDICATOR_PRIMARY`(핵심 22개)에만 `INDICATOR_NOTES`(뜻)를 달고 나머지 44개는 "나머지 N개 지표" 버튼 뒤에 뜻 없이 숨겼다. 사용자는 "어떤 건 뜻이 있고 어떤 건 없어 아쉽다"고 지적했다 — **전부 설명을 달거나, 최소한 감춘 지표도 뜻이 필요할 때가 있다는 것을 인정해야 한다.**

## Task 1: DART 값 레벨 코드 한글화 — 비고 코드·kind

**Files:**
- Modify: `docs/tool/se/app.js`
- Test: `tests/se/test_se_app_js.py`

**Interfaces:**
- Produces:
  ```js
  DART_REMARK_LABELS  // {"유":"유가증권","코":"코스닥","채":"채권상장법인","넥":"코넥스",
                       //  "공":"공정위 대상 기업집단","연":"연결대상 종속회사 있음",
                       //  "정":"정정신고","철":"철회"}
  formatRemark(rm)     // "코정" -> "코스닥 · 정정신고" (문자 단위 분해 후 매핑, 미지 문자는 원문 유지)
  KIND_LABELS          // {"public":"공모","private":"사모"}
  ```
- `formatValue`(기존 값 포맷 디스패처)가 `rm` 필드와 `kind` 필드를 만나면 이 함수들을 거치도록 배선한다. **컬럼 헤더 라벨(`LABELS.rm`, `LABELS.kind`)은 이미 있으니 건드리지 않는다 — 값만 고친다.**

**요구사항:**

- `formatRemark`는 **문자 단위로 분해**한다. 실측 `코정`처럼 두 코드가 붙어 나올 수 있다. 알려진 코드는 매핑값을, **모르는 문자는 원문 그대로 남긴다**(침묵하지 않는다 — SE-4h의 "값이 없으면 없다고 표기" 원칙과 같다).
- 빈 값·`"-"`는 `formatValue`의 기존 결측 처리(`isNoDataMarker`)를 그대로 탄다.
- `kind`는 정확히 `public`/`private` 두 값만 실측됐다. 그 외 값이 오면(미지) **원문을 그대로 보여준다** — 모르는 값을 지어내 번역하지 않는다.

- [ ] **Step 1: 실패하는 테스트를 쓴다**

1. `formatRemark("코정")` → `"코스닥 · 정정신고"`(구분자는 구현자가 정하되 일관되게)
2. `formatRemark("연")` → `"연결대상 종속회사 있음"`
3. `formatRemark("정")` → `"정정신고"`
4. 모르는 문자가 섞이면(`formatRemark("코X")`) 알려진 부분은 번역하고 `X`는 원문 유지
5. `formatValue("kind", "public")` → `"공모"`, `formatValue("kind", "private")` → `"사모"`
6. `formatValue("kind", "미지값")` → `"미지값"`(원문 그대로, 예외 없음)
7. `formatRemark("")`/`formatRemark(null)` → 결측 표기(기존 `isNoDataMarker` 경로)

## Task 2: 공시 목록 열 폭 개별화 + 소량 접힘 방지

**Files:**
- Modify: `docs/tool/se/app.js`, `docs/tool/se/index.html`
- Test: `tests/se/test_se_app_js.py`, `tests/se/test_se_page_assets.py`

**요구사항 A — 공시 목록 열 폭**

- `index.html`의 전역 `td{max-width:280px}`는 그대로 두되(다른 표에 영향 주지 않기 위해), **공시 목록 표에만** 열별 폭 힌트를 준다. 가장 단순한 방법: 공시 목록 렌더 시 `report_nm` 셀에 클래스(예: `.wide`)를 붙이고 CSS로 `max-width`를 늘리며, `flr_nm` 셀은 줄인다.
- 구체적 값은 임의로 정하되(예: `report_nm` 420px, `flr_nm` 140px), **가로 스크롤이 안 생기게** 전체 표 폭 예산 안에서 조정한다. 좁아진 열이 있으면 그만큼 넓어진 열이 있어야 표 전체 폭이 뒤틀리지 않는다.
