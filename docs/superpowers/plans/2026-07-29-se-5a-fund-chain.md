# SE-5a 자금 체인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 자금사용 내역 94행 나열을 **조달건 단위 흐름**으로 바꾼다 — 언제 얼마를 조달해 어떤 용도에 얼마씩 쓰겠다고 했는지가 한눈에 보이게.

**Architecture:** `app.js`에 순수 함수 `fundChain(records)`를 두어 납입일로 조달건을 묶고 용도별로 금액을 분해한다. 조달 공시(`disclosures`)와는 **날짜 근접으로 병치**하되 조인이라고 말하지 않는다. 렌더는 CSS 비례 막대(외부 의존성 0, 글자 선택 가능). `dart_risk_mcp/`·`se_server/`는 건드리지 않는다.

**Tech Stack:** 순수 ES5 스타일 JS, CSS flexbox, pytest + node 서브프로세스.

## Global Constraints

- **판정 금지 (v0.8.5).** "자금 유용", "용도 외 사용", "의심", "부적절" 같은 어휘를 쓰지 않는다. 조달·계획·집행은 **회사가 공시한 사실**이고, 우리는 그것을 정렬해 보여줄 뿐이다.
- **임계값 금지.** "계획의 N% 이상이 기타 용도" 같은 규칙을 만들지 않는다. SE-4g 사실 강조 규칙과 같은 기준: 부호·같은 레코드 두 값의 비교·DART 원본 값·core 산출물만 허용.
- **점수·등급·순위 금지.**
- **없는 연결을 만들지 않는다.** 아래 "배경"에서 확인했듯 **자금 용도와 도착지 법인을 잇는 열쇠가 데이터에 없다.** 병치는 병치라고 쓴다.
- **`dart_risk_mcp/`·`se_server/` 한 줄도 고치지 않는다.** MCP 도구 26개 무영향.
- **외부 의존성 추가 금지.** CDN·npm·새 파이썬 패키지 모두 금지. Chart.js는 이미 vendored지만 이 계획에서는 쓰지 않는다(사유는 Task 3).
- **DOM 주입 금지.** 데이터는 `textContent`로만.
- **다크·라이트 양쪽 정의.** 새 CSS 변수는 `:root`와 `:root[data-theme="light"]` 양쪽에.
- **로그아웃 잔류 금지.** 새 DOM이 `showGate()`에서 지워져야 한다.

## 배경: 실측으로 확인한 것

2026-07-29, 엔켐(`corp_code=01011526`)·제이스코홀딩스(`00164645`) 실 API. **아래 값은 픽스처에 그대로 쓸 실측값이다.**

> ⚠️ 이 절의 값은 **API 응답에서 뽑아 출력한 것**이다. 같은 저장소에서 계획 작성자가 자기가 만든 라벨을 응답값으로 옮겨 적어 화면이 통째로 빈 사고가 있었다(SE-4h). 여기 값을 의심하면 다시 재라.

### `fetch_fund_usage(corp_code, api_key, lookback_years=3)` 반환 형태

**행 목록**이다(봉투 아님). 각 행의 필드:

```
kind · year · tm · pay_de · pay_amount · plan_useprps · plan_amount ·
real_dtls_cn · real_dtls_amount · dffrnc_resn · flags
```

실측 행 하나(그대로 픽스처로 쓸 것):

```json
{"kind":"public","year":2023,"tm":"-","pay_de":"2021.10.26","pay_amount":0,
 "plan_useprps":"시설자금","plan_amount":13082000000,
 "real_dtls_cn":"시설자금","real_dtls_amount":13082000000,
 "dffrnc_resn":"-","flags":[]}
```

### ⚠️ 스펙 ②가 요구한 것 중 **만들 수 없는 것 3가지**

스펙 §7.1은 `② 자금 체인 — 조달건별 수직 흐름도. 폭이 금액에 비례. 조달 → 계획 → 집행 → 도착지 손익`이라고 적었다. 실측 결과:

1. **"도착지"를 이을 열쇠가 없다.** `plan_useprps`·`real_dtls_cn`은 상대방 법인명이 아니라 자유 텍스트 용도 분류다. 엔켐 실측 값 분포:
   `시설자금(8) · 운영자금(8) · 기타(8) · 해외공장 투자 및 운용자금(30) · 운영자금 및 타법인 증권 취득자금(6) · 국내 시설자금 및 운영자금(26) · 원재료 매입대금 및\n해외공장 증설자금(3) · -(2) · 타법인 증권 취득자금 및 \n운영자금(원재료 매입금)(1) · 운영자금(원재료 매입대금)(2)`
   **한 건에 용도가 여러 개 섞여 있고 금액 배분이 없다.** 개행(`\n`)이 값 안에 들어 있는 것도 실측이다.
2. **"계획 vs 실제" 대조가 성립하지 않는다.** 엔켐 94건 **전부 `plan_amount == real_dtls_amount`**(차이 0건). `dffrnc_resn`이 `-` 아닌 건 0건, `flags` 붙은 건 0건. 분기마다 누적치를 다시 보고하는 구조라 어긋난 지점이 나오지 않는다.
3. **`pay_amount`가 전 행 0이다.** 조달 금액이 응답에 없다. **"폭이 금액에 비례"의 폭은 `plan_amount`에서 얻어야 한다.**

**이 세 가지를 우회하는 코드를 쓰지 마라.** 없는 것을 있는 것처럼 만드는 것이 이 저장소가 가장 자주 저지른 실패다.

### 만들 수 있는 것 — 납입일 묶음은 실제로 정보가 된다

`pay_de`로 묶으면 조달건이 나온다. 엔켐 실측 11건 (**픽스처와 검증 기대값의 원본**):

| `pay_de` | 행 수 | 계획 합계 | 용도 종류 |
|---|---:|---:|---:|
| `-` | 2 | 0 | 1 |
| `2021.05.13` | 6 | 114,000,000,000 | 1 |
| `2021.05.14` | 12 | 66,000,000,000 | 1 |
| `2021.10.26` | 24 | 768,240,000,000 | 3 |
| `2021.11.29` | 6 | 540,000,000,000 | 1 |
| `2023.05.11` | 12 | 378,000,000,000 | 1 |
| `2023.06.02` | 12 | 1,320,000,000,000 | 1 |
| `2023.07.07` | 12 | 600,000,000,000 | 1 |
| `2024.11.29` | 5 | 1,250,000,000,000 | 2 |
| `2026.01.05` | 1 | 18,700,000,000 | 1 |
| `2026.01.30` | 2 | 10,500,000,000 | 1 |

**⚠️ 행 수가 용도 종류보다 훨씬 많다.** 같은 (납입일, 용도) 조합이 여러 번 반복된다 — 보고서마다 같은 누적치를 다시 낸 것이다. **그대로 합산하면 금액이 중복 계상된다.** 반드시 (납입일, 용도)별로 **하나만** 남겨야 한다. 어느 것을 남길지는 Task 1에서 정한다.

### 조달 공시는 있다 — 다만 확정 조인은 아니다

`fetch_company_disclosures` + `match_signals`로 5년 조회 시 조달 신호(`CB_BW`·`3PCA`·`RIGHTS_UNDER`·`EB`·`RCPS`) 공시 **49건**. 실측 예:

```
20260123  주요사항보고서(전환사채권발행결정)          CB_BW
20260120  주요사항보고서(전환사채권발행결정)          CB_BW
20251226  주요사항보고서(전환사채권발행결정)          CB_BW
```

**공시일 형식은 `20260123`(하이픈 없음)이고 납입일은 `2021.10.26`(점)이다.** 형식이 다르므로 비교 전에 숫자만 남겨 정규화해야 한다 — 기존 `axisSortKey`가 정확히 그 일을 한다(SE-4f에서 `numeric("2018.05.07")`가 `null`을 돌려줘 정렬이 죽은 사고 이후 만들어진 것). **새 파서를 쓰지 말고 그걸 재사용하라.**

### 회사에 따라 통째로 빈다

**제이스코홀딩스 26건은 `plan_useprps`·`real_dtls_cn`·`pay_de`가 전부 `-` 다.** 용도도 납입일도 없다. `pay_amount`도 0.

즉 **조달건이 하나도 안 만들어지는 회사가 실제로 있다.** 이 경우 화면이 "해당 기간에 보고된 자금사용 내역이 없습니다"가 아니라 **"내역은 있으나 납입일·용도가 공시되지 않았습니다"** 라고 말해야 한다 — 둘은 다른 사실이다.

## Task 1: `fundChain` — 조달건 묶음과 중복 제거

**Files:**
- Modify: `docs/tool/se/app.js`
- Test: `tests/se/test_se_app_js.py`

**Interfaces:**
- Consumes: `isNoDataMarker(v)` (`null`/`""`/`"-"`를 결측 판정), `markNumber(v)`, `axisSortKey(v)` — **모두 이미 있다. 재사용하라.**
- Produces:
  ```js
  fundChain(records) → [
    {
      pay_de: "2021.10.26",     // 납입일. 결측이면 null
      sort_key: "20211026",     // axisSortKey 결과. 정렬·매칭용
      total_plan: 768240000000, // 용도별 plan 합 (중복 제거 후)
      uses: [
        { purpose: "시설자금", plan: 13082000000, real: 13082000000,
          diff_reason: null,    // dffrnc_resn 이 결측이면 null
          rows: 8 }             // 이 (납입일,용도)로 보고된 행 수 — 중복 재보고 횟수
      ],
      row_count: 24             // 이 조달건에 속한 원본 행 수
    }
  ]
  ```

**요구사항 — 중복 계상 방지가 이 태스크의 핵심이다**

엔켐 `2021.10.26`은 **24행이지만 용도는 3종**이다. 같은 (납입일, 용도)가 8번씩 반복 보고됐다. 그대로 더하면 계획 합계가 8배가 된다.

- **(pay_de, plan_useprps)별로 하나만 남긴다.**
- 남길 기준: **`plan_amount`가 가장 큰 행.** 계획 금액이 보고 시점마다 바뀌는 사례가 이미 확인됐고(SE-4f: 엔켐 운영자금 342.9억 → 352.9억), 최신 보고를 고를 수 있는 신뢰할 만한 필드가 없기 때문이다 — `year`는 사업연도이고 `tm`은 `-`이며 `reprt_code`는 core 정규화에서 탈락한다. **최댓값을 고르는 이유를 코드 주석에 남겨라.** 이건 임의 선택이 아니라 "고를 근거가 없어 가장 큰 보고치를 쓴다"는 명시적 결정이다.
- 용도 텍스트의 **개행을 공백 하나로 정규화**한다(실측: `"원재료 매입대금 및\n해외공장 증설자금"`). 정규화 후 값이 같으면 같은 용도다.
- `pay_de`가 결측(`-`)인 행도 **버리지 않는다.** `pay_de: null`인 묶음 하나로 모으고, 렌더가 그 사실을 말한다.
- 결과는 `sort_key` **내림차순**(최신 조달이 위).
- `records`가 배열이 아니면 `[]`.

## Task 2: 조달 공시 병치 — 조인이 아님을 코드와 화면 양쪽에 남긴다

**Files:**
- Modify: `docs/tool/se/app.js`
- Test: `tests/se/test_se_app_js.py`

**Interfaces:**
- Consumes: Task 1의 `fundChain` 결과, `disclosures` 섹션 레코드(`{rcept_no, rcept_dt, report_nm, ...}`), `axisSortKey`
- Consumes: 공개 뷰어의 신호 분류 — SE-4f에서 `docs/tool/signals-data.json`을 `fetch("/signals-data.json")`로 불러 `matchSignals`로 쓰는 경로를 이미 만들었다. **그걸 재사용하라.** 같은 공시를 두 화면이 다르게 분류하면 그 자체가 결함이다.
- Produces:
  ```js
  fundChainDisclosureHints(chain, disclosures, signalsData, windowDays = 90) → {
    "20211026": [ { rcept_no, rcept_dt, report_nm, days_before } ]
  }
  ```
  키는 조달건의 `sort_key`. 값은 **납입일 이전 `windowDays` 이내**의 조달 신호 공시.

**요구사항 — 이 태스크에서 가장 중요한 것은 확실성 표기다**

- 매칭 대상 신호 키: `CB_BW`·`3PCA`·`RIGHTS_UNDER`·`EB`·`RCPS`. `signalsData`를 못 받으면 `{}`를 돌려주고 **화면은 이 블록만 빠진다**(SE-4f의 폴백 방식과 같다).
- **납입일 "이전"만 본다.** 조달 결정은 납입에 앞선다. 이후 공시를 끌어오면 인과가 뒤집힌다.
- **날짜 형식이 다르다.** 공시일 `20260123`, 납입일 `2021.10.26`. 반드시 `axisSortKey`로 정규화해 비교하라. **새 파서를 만들지 마라** — `numeric()`은 점을 거부해 `null`을 돌려준다(SE-4f 사고).
- `days_before`를 함께 돌려준다. 화면이 "며칠 전"을 말할 수 있어야 근접의 정도를 사용자가 판단한다.
- **한 조달건에 여러 공시가 걸릴 수 있다.** 하나로 좁히지 마라 — 좁히는 순간 우리가 판정하는 것이 된다. 전부 돌려주고 화면이 나열한다.
- **`windowDays`는 임계값이 아니라 조회 창이다.** 기본 90일이며 화면에 그 값을 명시한다("납입일 이전 90일 이내 조달 공시"). 이 수치로 무언가를 판정하지 않으므로 Global Constraints의 임계값 금지에 저촉되지 않는다 — 다만 **화면에 반드시 창 크기를 적어라.** 적지 않으면 "이게 그 조달건이다"라는 단정으로 읽힌다.

- [ ] **Step 1: 실패하는 테스트를 쓴다**

검증할 것:

1. 납입일 **이전** 공시만 잡힌다 — 하루 뒤 공시는 제외된다
2. 창 밖(91일 전) 공시는 제외된다
3. **한 조달건에 2건 이상 걸리면 2건 다 돌려준다**
4. `days_before`가 맞게 계산된다
5. `signalsData`가 `null`이면 `{}`를 돌려주고 예외가 없다
6. **조달 신호가 아닌 공시**(예: 분기보고서)는 잡히지 않는다
7. 공시일 형식이 `20211020`(하이픈 없음), 납입일이 `2021.10.26`(점)일 때 **정상 매칭된다** — 형식 정규화 회귀 방어

## Task 3: 렌더 — 비례 막대와 조달건 카드

**Files:**

- Test: `tests/se/test_se_app_js.py`, `tests/se/test_se_page_assets.py`

**Interfaces:**

- Consumes: `_RENDER_SECTION_HARNESS` / `run_render_section` — 실렌더 검증용. **소스를 grep하는 테스트를 쓰지 마라.** 이 저장소는 배선 누락으로 일곱 번 당했고 매번 grep 테스트가 초록이었다.

**왜 Chart.js를 쓰지 않는가**

이 표현은 "한 조달건의 계획 금액을 용도별로 나눈 비율"이다. 축도 시간도 없다. **CSS flexbox 비율 막대면 충분하고**, 그 편이 (a) 글자를 막대 안에 두어 선택·복사가 되고 (b) 캔버스 destroy 관리가 필요 없고 (c) 다크·라이트 전환이 CSS 변수로 자동이다. 이 판단 근거를 코드 주석에 남겨라.

**렌더 구조 (조달건 하나 = 카드 하나):**

```
2021.10.26 조달 · 계획 합계 7,682.4억                      [← 헤더]
┌──────────────────┬────────┬───────────────────────────┐  [← 비례 막대]
│ 국내 시설자금…    │ 시설자금│ 운영자금                   │
└──────────────────┴────────┴───────────────────────────┘
 용도            계획        보고된 집행    차이 사유
 시설자금        130.8억      130.8억        —
 운영자금        352.9억      352.9억        —
 ⓘ 4개 보고서에 같은 금액이 반복 보고돼 용도별로 한 건만 남겼습니다
 ⓘ 납입일 이전 90일 이내 조달 공시 2건 · 클릭하면 원문
```

**요구사항:**

- **막대 폭은 `plan / total_plan`.** `total_plan`이 0이면 막대를 그리지 않는다(0으로 나누지 마라).
- **막대 조각이 너무 좁으면 라벨이 안 들어간다.** 실측에서 `2021.10.26`은 시설자금 130.8억 / 전체 7,682.4억 = **1.7%** 다. 최소 폭을 두고 라벨은 넘치면 감춘 뒤 표에서 읽게 한다 — **막대에서 사라진 정보가 표에는 반드시 있어야 한다.**
- **`rows > 1`이면 반복 보고 사실을 표기**한다(위 ⓘ 첫 줄). 우리가 골라 버린 것이 있음을 숨기지 않는다.
- **`pay_de`가 `null`인 묶음**은 "납입일이 공시되지 않은 내역"으로 제목을 달고 맨 아래에 둔다.
- **조달건이 하나도 없을 때**(제이스코 형태): `"자금사용 내역 N건이 있으나 납입일·용도가 공시되지 않았습니다"`. **"내역이 없습니다"라고 쓰면 거짓이다** — 내역은 있다.
- 공시 힌트는 클릭 시 기존 `openDocPanel(rcept_no)`로 원문 패널을 연다(이미 있는 배선 재사용).
- 새 CSS 변수는 `:root`·`:root[data-theme="light"]` 양쪽에.
- `showGate()`가 지우는 범위 안에 들어가는지 **실행으로 확인**한다.
