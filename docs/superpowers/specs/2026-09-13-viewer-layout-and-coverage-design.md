# 뷰어 레이아웃 다열화 + 미노출 정보 표면화 (2026-09-13)

## 왜

공개 리스크 뷰어(`docs/tool/index.html`)의 결과 대시보드가 **패널을 전부 1열로 쌓는다**.
`.mainarea`에 `max-width`가 없어 뷰포트 폭을 다 쓰는데도 가로를 안 쓰고 세로로만 길어진다.
실측(1920px): 코아스 **7,369px = 6.8화면** · 제이스코홀딩스 7,106px · 삼성전자 4,632px.

같은 자리에서 **core는 계산하는데 뷰어가 안 그리는 것**도 드러났다 — 적자 시점 배당 유출,
내부자 매수·매도 클러스터와 「매도 ±30일 부정 공시」의 방향, 주요 결정 상대방. 가로 공간이
생기면 그것들을 놓을 자리가 함께 생긴다.

**점수·등급은 여전히 매기지 않는다**(v0.8.5). 레이아웃도 위험도 순서를 암시하지 않는다.

## 하지 않기로 한 것 (근거)

| 후보 | 왜 안 하나 |
|---|---|
| CSS multi-column(`columns`) | `.mzn-scroll thead`의 sticky가 multicol 프래그먼트에서 죽고, `break-inside:avoid` 요소가 컬럼 높이를 넘으면 **조용히 잘린다**. 12개 패널이 `loadDeepBlocks`로 나중에 길어져 어디가 잘릴지 예측조차 못 한다 |
| `grid-auto-flow: dense` | 빈 칸을 메우려 순서를 재배치하면 위험도 순서를 암시한다 |
| 전폭 span(`.wide`) | **실측으로 뺐다** — 아래 표 |
| `majorstock`(5% 대량보유) 화이트리스트 | INSIDER 패널이 「이것은 5% 대량보유 보고가 아닙니다」라고 명시하고 그쪽을 MCP로 넘기는 계약이다(2026-08-30 라벨 정정). 섞으면 그 구분이 흐려진다 |
| `fnlttSinglIndx`(재무지표) 화이트리스트 | core가 2026-08-28에 **일부러 뺐다** — 회전율 `idx_val`이 ×100 스케일로 와 「재고자산회전율 4780.49회」가 나왔다. 지금은 추가 호출 0회로 직접 계산한다 |

### `.wide`를 뺀 실측 (코아스 1920px · 딥 블록 10개)

    전               7,369px (6.8화면)
    후 2열           6,033px (5.6화면)   ← 채택
    후 3열           6,135px             트랙 528px · MEZZANINE이 한 행 지배
    후 2열 + .wide   6,558px             wide 3개가 연달아 행마다 구멍

표가 넓은 패널 셋(FINANCIAL CORE 6열 · TURNOVER TREND 5열 · MEZZANINE 5열+표 2개)에 2트랙을
주니 그 행의 남은 트랙이 통째로 비어 **격자 높이가 되레 541px 늘었다**. 셋이 DOM에서 연달아
있고 dense 금지라 그 구멍을 메울 방법이 없다.

`.wide` 없이도 안전한 이유는 **표를 감싼 div가 이미 `overflow-x:auto`**여서다 — 트랙 388px에서
TURNOVER 표 498px가 표 안에서만 가로 스크롤되고 패널·페이지는 넘치지 않는다(실측). 그래서
브레이크포인트를 표 폭에 맞춰 좁힐 이유가 없다.

### 열 수 결정

| 뷰포트 | 열 | 코아스 페이지 높이 |
|---|---|---|
| ~1279px | 1 | 8,344px (기존 동작 유지) |
| 1280~2279px | 2 | 1280 → 6,649 · 1440 → 6,348 · 1920 → **6,033** |
| 2280px~ | 3 | 2560 → **5,937** |

1920px에서는 2열(6,033)이 3열(6,135)보다 낫고, 2560px에서 역전된다(3열 5,937 < 2열 6,012).
트랙이 넉넉해져야 3열이 이긴다 — MEZZANINE(1,177px)이 한 행을 지배해 트랙이 좁을 때 3열은
두 칸을 낭비한다.

### PR 0 — 딥 블록 반응형 격자

`renderDash`의 CONTROL CHANGE부터 AUDIT OPINION까지를 `.deepgrid`로 감싼다. 위쪽 서사 구간
(헤드라인·KPI·HEAVIEST·TIMELINE·SIGNAL COMMENTARY·CAPITAL RHYTHM·PATTERN WATCH)은 읽는 순서
자체가 의미라 전폭을 유지하고, `convoPanel`(GO DEEPER)은 CTA라 격자 밖에 둔다.

`tests/test_viewer_deep_grid.py`가 잠그는 것 — 태그 균형(`innerHTML`은 불균형을 **조용히
교정**해 눈으로 못 찾는다) · 딥 블록 12개가 전부 격자 안 · `convoPanel`은 밖 ·
`grid-auto-flow` 부재 · 패널 `overflow` 부재 · `.wide` 부활 방지 · 컨테이너가 스피너로 시작
(빈 칸은 「자료 없음」으로 읽힌다).

### PR 1 — 적자 시점 배당 유출

`loadDividendCore`가 이미 3년치 `alotMatter`를 받아 온다. core `detect_dividend_drain`이 쓰는
`se`/`thstrm`/`reprt_code`/`bsns_year`가 전부 그 응답 안에 있어 **새 호출 없이** 기존 배당
패널을 확장한다. core가 다는 두 라벨을 그대로 단다 — 「연결·지배지분 기준」(비지배지분 제외라
총 당기순이익과 부호가 다를 수 있다), 원 단위 환산.

상수는 하드코딩하지 않고 `signals-data.json`으로 내보내 받는다.

### PR 2 — 내부자 클러스터 + 방향

⚠ **두 규칙을 조용히 합치지 않는다.** 뷰어는 `elestock` 기준 60일/+1.0%p 매집을 이미 한 가지
발화하고, core의 클러스터는 `hyslrSttus` 기준 30일/0.5%p다 — 축·엔드포인트·임계가 전부 다르다.
어느 축인지 패널에 밝힌다.

⚠ `detectInsiderPreDisclosure` 이식 시 **`gap_signed`를 유지**한다. `abs()`를 쓰면 「매도 N일
전」과 「N일 후」가 뒤집혀 뜻이 정반대가 된다 — core가 2026-08-30에 고친 바로 그 결함이다.

### PR 3 — 시각화

없는 차트를 새로 만들지 않고 있는 자산을 넓힌다 — `.bar` · `.density` 12칸 · lane/dot SVG.
차트 코드 첫 줄을 쓰기 전에 `dataviz` 스킬을 로드하되 팔레트는 뷰어의 `--c1`~`--c9`를 쓴다
(외부 의존 0 · 카테고리 색은 이미 정해진 계약).

### PR 4 — 채무증권 5종

`fetch_debt_balance`는 **합계 행만** 읽고 금액은 `sm`, 만기 구간은 `yy1_below` 계열이다
(`remndr_amount`는 존재하지 않는 필드였다). 5콜이라 **지연 로드**. 화이트리스트 3곳
(`api/[endpoint].js` · `relay/worker.js` · `scripts/dev_relay.py`)을 동시에 고친다.

### PR 5 — 주요 결정 상대방

DS005를 화이트리스트에 넣지 않는다. 뷰어는 이미 원문에서 상대방·관계·금액·자기자본 대비를
읽고, core도 DS005 실패 시 같은 폴백을 한다. 빠진 것은 DS005 전용 필드(외부평가·풋옵션)이고
**같은 원문 ZIP**에서 들어 올린다. ⚠ 자산 대비는 자산총액이 실제로 있을 때만 낸다 —
자기자본으로 몰래 대체하지 않는다.

### PR 6 — 감사인 교체

지금은 3년 감사인명을 비교해 교체를 **추측**하고 「표기 차이일 수 있음」으로 얼버무린다.
`adtServcCnclsSttus` 계열이 그것을 기간 **사실**로 바꾼다. ⚠ 감사보수 **절대 금액은 표기하지
않는다**(단위 천원/백만원 혼용 — v0.8.0 결정).

### PR 7 — 비교 화면

각 회사 스캔이 **이미 만든 것만** 재사용한다. 확장 표는 3개사 상한, 겸직은 5개사 유지.
**상한을 화면에 사실로 적는다.**

## 공통 원칙

- **조용한 절단 금지** — 새 목록마다 「전체 N건 중 M건 표시」. 내부 스크롤은 절단이 아니라
  허용, `slice`는 절단이라 고지 필수.
- **패리티 등록** — `tests/test_viewer_twin_parity.py`가 새 이름 짝을 자동 신고한다. 이식
  함수는 `_FUNCS`에 넣어 실제 비교를 붙이거나 `_COVERED_ELSEWHERE`에 사유를 적는다.
- **판정 어휘 금지** — core의 MCP 산문(「가능성 검토 권장」·「전조 가능성」)을 그대로 옮기지
  않는다. 뷰어는 사실만 적는다.
- **실패 ≠ 부재** — 조회 실패는 `fetchFailHTML` 계열로 그 사실을 적는다.
- 버전·CHANGELOG는 PR에 넣지 않는다(머지 후 릴리스 커밋에서 한 번에).

## 검증

각 PR마다 전체 스위트(`pytest tests/ -q`, 키 없음·있음 두 조건) + 로컬 릴레이
(`scripts/dev_relay.py`)에 붙여 라이브 3사(코아스 = 딥 블록 짧음 · 제이스코홀딩스 = 조건부
패널 발화 · 삼성전자 = `CUR.truncated` + 표 최장) 대조. 레이아웃은 폭 760/1280/1440/1920/2560
다섯 곳에서 격자 높이·패널 넘침·페이지 가로 스크롤·콘솔 오류를 잰다.
